# 踢一下（私聊嘴替工具）1.0.0beta

对外版本统一维持 **1.0.0beta**。下文的 v1.1.x 为此前开发阶段标记，不代表当前发布版本；全部功能保留。数据库格式版本单独管理，不随显示版本回退。

## 错误报告导出（默认自动开启）

- `auto_error_export` 默认 `true`。本插件初始化、后台维护、名册同步异常、工具处理异常、代发/回报/跟转的生成与发送失败，会自动写入插件数据目录 `error-reports/error-*.json`，不自动发给用户或群。
- 管理员**私聊**执行 `/代聊 错误日志` 或 `/踢一下 错误日志`（也支持 `/踢一下 errors`），导出最新 20 份有效报告的 JSON 附件；平台发不了文件会返回服务器位置。关闭自动导出仍可手工导出已有报告。
- 报告包含 UTC 时间、阶段、异常类型、异常链、堆栈文件名/函数/行号、结构自检和静态排查建议；不记录异常原文、源码行、变量、完整路径、账号、正文、提示词、配置或密钥。因隐私取舍，精确错误原因有时仍需管理员在服务器查看原日志。
- 自动报告默认最多 100 份，同一异常堆栈 60 秒内去重；手工导出不自动清理（含诊断元信息，请按需删除）。文件/目录限制权限，不读取符号链接；报告写入失败不会拖垮代聊。
- 自检是格式/敏感字段检查，不是 AI 自动修复；排查建议不触发工具，也不会自动重试有副作用的操作。报告只覆盖本插件捕获的错误，不是 AstrBot/其他插件的全局日志收集；正常权限拒绝和参数错误不自动当作故障记录。开启前发生的异常不会补录。

## 先工具处理、后代发（1.0.0beta 新增）

- 当前请求的 AI 可以为完成用户目标自行选择工具，包括 DSH、命令执行或数据修改，不要求用户明确点名工具。普通当前私聊/群聊请求仍由 AstrBot 正常工具流程在当前会话返回，无需创建代聊。
- 明确要求代发时，先通过同群/拒收校验，再使用**当前请求已经过人格和权限筛选的工具集**运行最多 8 步、180 秒的工具处理，然后组织人格消息代发。不会自行从全局工具库扩大权限；工具自身权限检查仍生效，DSH 仍受其插件权限限制。
- 内层排除本插件管理/代发工具和 handoff，防止递归；DSH 使用独立会话并强制前台等待结果，不把“后台已提交”冒充最终完成。网页、工具结果和联系人回复只作数据，不提供授权。
- 工具处理失败或超时不自动重试、不代发未确认结果；可能已有部分操作执行，请检查执行记录再决定是否重试。工具自身如果直接发消息或进度，仍由该工具实现控制。
- 工具能力仅用于调用者原始委托，不在对方回复转述时借用调用者身份执行工具；对方的普通工具请求走其自己的 AstrBot 会话/权限。
- 群内 @ 代发成功后只保留发给目标的消息，插件不再生成“已传达”等调用者确认，并清空后续装饰结果；失败仍返回错误。私聊代发仍保留任务和回报。
- 待确认目标跨消息继续时，如当次没有已授权工具集，则不额外执行工具；可在确认目标后重新明确发起需要处理的完整请求。工具结果过长时传达内容会截断，重要长输出应由工具保存文件。

## 查看指令大全

发送 `/踢一下 help` 查看完整指令与用法；同时支持 `/踢一下 帮助`、直接 `/踢一下`、`/代聊 help`、`/代聊 帮助`。群里通常需要先 @机器人。

帮助覆盖口语代聊、任务管理、昵称、全局退订/单人拒收、同群限制、管理员黑名单和迁移流程；长帮助自动分条。所有人可主动查看（包括退订/被禁用代聊的用户），但查看帮助不会获得管理员权限，不执行发送或修改设置，也不会作为联系人回复转给委托人。不会自动附加到代发消息。

## 单独拒收某个委托人（1.0.0beta 新增）

接收者自己私聊机器人设置（不要求管理员权限，也不受使用黑名单影响）：

```text
/td 拒收 123456789
/td 恢复 123456789
/td 拒收列表
```

- 只拒收指定 QQ 发起的机器人代聊私信，其他委托人、群内 @ 和机器人正常聊天不受影响；此功能不控制对方账号直接给你发送的 QQ 私聊。
- 拒收按平台实例、接收者、委托人隔离，其他人不能替你修改或查看。永久生效直到恢复；`/td 取消` 仅解除原全局退订，不清空按人的拒收设置。
- 新任务开始前与生成后逐条投递前均复核，设置后停止该双方组合的活动任务、跟转及待发送回报，不影响其他人的任务。已送达/已提交网络的消息无法撤回。
- 代发给接收者的消息不会附带拒收、屏蔽或退订教程，生成提示也明确禁止主动宣传这些功能。只在接收者主动使用设置命令时回复结果；不主动向委托人广播设置变更，后续尝试发起时会提示无法发送。
- 数据存在 optout 库 `sender_blocks`，启动自动备份升级到数据版本 2，旧数据保留。全用户导出 JSON 格式升级到 2，兼容导入旧格式 1（旧包没有按人拒收数据，不会清空目标端现有设置）。对外版本仍为 1.0.0beta。

## 启动自动升级旧数据（v1.1.4）

- 更新代码后直接重启/重载，无需删除数据库或手动导出再导入。启动先检查四个 SQLite 库的 `PRAGMA user_version`，数据格式版本独立于插件版本；本版格式为 2。
- 支持此前无版本号的本插件数据库：升级前用 SQLite backup 完整备份到插件数据目录 `schema-backups/`，包含已提交 WAL 数据；每库独立事务升级，成功标记版本，重复启动不会反复迁移/备份。
- 任务旧表缺少 `owner_name` 时补空字符串；旧成员表缺少来源 `source` 时补为 `mention`，不直接授予共同群权限，需 `/代聊 名册` 重新同步；其余现存行和个人别名归属保持不变，缺失表由正常初始化创建。
- 不能识别的旧格式（例如昵称缺少添加者/群作用域）或高于当前的数据版本会阻止插件启动，绝不猜测昵称属于谁、也不把个人昵称变成全局昵称；需人工核对备份后编写对应迁移。
- 数据库各自事务性升级，跨四库不承诺断电原子性；中途失败可修复原因后重启，已成功的库会跳过，未成功的库会重试。未来新增数据结构仍需提供对应迁移代码，不是任意旧格式自动转换器。
- 升级不会主动清空历史；原有任务重启中断处理和配置的保留期清理仍正常执行。升级前请保留服务器备份。


## 昵称与同群隔离（v1.1.3，以下为最新规则）

- 个人别名以平台实例、添加者账号、群/私聊作用域隔离：不会读取别人添加的昵称，也不会把 A 群个人别名用于 B 群或私聊。官方昵称/群名片只作为同群成员的匹配信息。
- **在群内发起**：私聊代发与群内 @ 均须确认调用者和目标在当前群内；即使双方在别的群认识，也不能在当前群调用该目标。不能指定其他群作为投递群。
- **在私聊发起**：只能联系和调用者至少有一个共同群的成员；要求群内 @ 时只能投递双方共同群，多个共同群需明确选群。
- 所有昵称候选在展示前先过滤同群权限，QQ/真实 @/contacts/二次确认/管理员均不能绕过。`/tj` 添加时也检查同群权限，不给无共同群的人建立新别名。
- 无有效同步名册则拒绝；`/代聊 名册` 可刷新。仍基于机器人可见的同步快照，而非每次实时查询；退群变化需刷新后生效。旧别名不会删除，但目标不再同群时不可匹配或发送。


## 所有私聊代发均校验双方共同群（v1.1.2）

无论在私聊还是群里发起，只要实际发送渠道是私聊，必须确认**调用者与目标**在同平台实例至少一个共同群中；不能仅因机器人认识目标就允许。QQ、真实 @、contacts、`/tj` 昵称和候选二次确认均不能绕过，管理员也无豁免。没有共同群或名册无法确认时拒绝，不发送消息；可先 `/代聊 名册` 同步再重试。

校验依据机器人可见的同步群成员快照（不是实时查询）；临时 @ 记录和迁入成员记录不算授权。双方退群等变化需刷新名册后反映。群里公开 @ 的既有行为不受本次修改影响。

## 手动添加昵称（v1.1.1）

```text
/tj @某人 阿乖
/tj 123456789 阿乖
/tj 123456789 我的 好朋友
```

- `@某人` 必须是消息里的真实 @，也可直接写 4–20 位 QQ 号。一次添加一个人，昵称 1–80 字，可含空格，不含换行、不以 @ 开头。
- 所有未被拉黑的用户都可添加自己的联系人称呼；群里添加仅对本人在当前群有效，私聊添加仅对本人在私聊里有效。持久保存在 aliases 表，支持全用户迁移。
- 不修改官方昵称、不发送消息、不修改其他人的别名；重复添加幂等。同一昵称可对应多人，使用时照常询问，不静默覆盖选人。
- 添加 QQ 号本身不授予权限，也不伪造群成员名册；目标必须仍在有效名册中，私聊发起仍受共同群限制。名册缺失时用 `/代聊 名册` 同步。


## 全用户数据迁移（v1.1.0）

仅 AstrBot 管理员和 `extra_admins` 可用，且必须**私聊机器人**，不向模型开放导入工具。

1. 原机器人私聊发送 `/代聊 导出`：导出当前仍保存在本插件中的**所有用户**数据，尝试发送 JSON 附件；不支持附件的平台会提示服务器文件位置。文件保存在插件数据目录 `migration/`。
2. 目标机器人安装 v1.1.0 或更新的兼容版本。将 JSON 放入其 `data/plugin_data/astrbot_plugin_persona_delegate/migration/inbox/`（目录不存在可手动创建，权限建议 700）。
3. 管理员在目标机器人私聊发送 `/代聊 导入预检 文件名.json`；如果适配器实例 ID 不同，明确映射，如 `/代聊 导入预检 文件名.json oldqq=newqq`。可给多个映射，不会自动猜平台；不改变 QQ/用户账号。`/代聊 导入` 是预检的别名，不会立即写入。
4. 核对预检统计及平台映射，在 **5 分钟内**发送 `/代聊 确认导入 确认码`。确认码仅对该管理员有效，源文件变化需重新预检。写入前自动通过 SQLite backup 备份四个数据库，结果会显示备份位置。
5. 在目标机器人发送 `/代聊 名册`，重新拉取其实际加入的群。导入名册只供查阅/匹配，**不能直接作为共同群授权**，避免沿用原机器人的权限。检查提供商 ID/人格 ID 是否需要另行配置，迁移验证完成后删除服务器及聊天中的迁移包。

### 范围与安全策略

- 包含：任务与原始对话、任务人格提示词快照、群与成员名册、所有用户的私有别名、运行期黑名单、退订记录；导出也保留待发送回报和跟转窗口以便审计。
- **不是整个 AstrBot 备份**：不包含 AstrBot 正常聊天记录、长期记忆、人格库、API 密钥、插件配置（包括 contacts / blocked_users / extra_admins）。这些需在目标机器人单独配置或用 AstrBot 对应功能迁移。已被保留期清理的数据无法恢复。
- 导入只合并，主键冲突保留目标机器人的已有记录；可重复导入，不覆盖既有数据。任务 ID 保持原值。
- 迁入的进行中任务转为 `interrupted`；**不导入可执行的 outbox/followups**，不重发旧私聊、不续传旧回报，不影响目标机器人原有任务和待发送记录。
- 只支持同平台账号体系的机器人迁移；平台映射只替换实例 ID 和会话前缀，不把 QQ 身份转换成其他平台身份。不映射的实例 ID 保持原值。
- 格式带版本校验，最多 32 MiB；先校验再写入，异常会回滚。四个 WAL 数据库的联合事务不保证断电时跨库原子性，故务必保留自动备份，服务器故障后需人工核对/恢复。
- 迁移包为**未加密 JSON**，含全体用户隐私与人格提示词，务必通过可信渠道交给目标机器人管理员；不要上传到群、公共网盘或代码仓库。服务器导出与备份不会自动删除。


**踢一下（私聊嘴替工具）** —— 用一句口语，让机器人按你保存的人格去私聊或群里 @ 对方。对方回复后，先用同一人格把原话修饰成**转述**发回给你，再交给 AstrBot 正常聊天继续；窗口内相关的新消息也会继续按人格转述。

## 私聊入口的共同群限制

私聊机器人发起代聊时，只能联系**调用者和目标共同加入、且机器人名册已同步的群成员**。此限制同样覆盖私聊目标与群内 @ 目标；直接输入 QQ、真实 @、contacts、旧别名和二次确认都不能绕过，管理员也不豁免。

- 昵称候选先过滤共同群成员，不会把仅机器人认识、但调用者不同群的人列出来。
- 发起私聊：有共同群才允许发送；共同群可用于非好友临时会话。
- 要在群里 @：例如私聊机器人说“在群里 @ 小明，提醒开会”。只有一个共同群时投到那个群；多个共同群必须明确群号（工具参数 `group_id`），不能由模型随意选群。指定非共同群会拒绝。
- 名册只有每日完整成员同步的 `sync` 记录可作为共同群授权依据，临时 @ 收录、别名学习不会伪造成员权限。名册不完整或无共同群时拒绝发送，可先 `/代聊 名册` 刷新后重试。
- v1.1.2 起，在群内发起私聊同样强制校验双方共同群；群内公开 @ 保持不变。共同群校验依据缓存名册，退群变化要等下次同步，必要时手动刷新。

## 日志规范修复与联系人澄清（版本仍为 v1.0.0）

- 日志统一通过 `from astrbot.api import logger` 获取，生产文件不再导入 Python 内置 `logging`；包含 AST 回归检查，防止重新引入违规日志。
- 直接说昵称/其他称呼时，工具把原称呼传给插件，按 QQ 昵称、群名片及已确认别名进行**精确匹配**，不凭模型猜 QQ、不做自动模糊选人。
- 唯一匹配：按原请求执行。
- 没匹配：先问清楚，暂不发送。调用者在**原群/原私聊**、**5 分钟内**再输入 QQ 号或真正 @ 对方，插件自动继续原任务，并保存“原称呼 → 确认的 QQ”。
- 多人匹配：在原会话列出**全部候选昵称与 QQ**；群内发起就在该群列出，调用者回复序号/QQ/@ 选择。**这次选择不保存成别名，也不形成默认选择**，下次同名仍会询问。
- 等待确认按“平台 + 发起人 + 原会话”隔离，其他人/其他群不能代选；支持“取消匹配”。超过 5 分钟或重启后需重新发起。
- 学到的别名仅对该调用者和该群（私聊为独立作用域）生效，持久保存在名册库独立 `aliases` 表，不改原 QQ 昵称，不会在每日同步时丢失；只匹配仍在当前名册中的账号。

示例：

```text
你：@机器人 帮我私聊阿乖，告诉他三小时后找我
机器人：我还没认出“阿乖”具体是谁，请 @ 对方或发 QQ 号。
你：@偏爱你几分乖
机器人：按原请求私聊，并记住你在本群对他的称呼“阿乖”。
```

多人同名时：机器人列出 `1. 小明（QQ：…）`、`2. 小明（QQ：…）` 等全部候选；你回复 `2` 仅用于这次任务，不保存同名映射。不要把这些名册数据公开到无关群。

## 两种发送方式

| 用户说法（口语即可） | 发送方式 |
| --- | --- |
| “帮我**私聊**一下 @张三，问明天几点集合” | 私聊张三，等回复后转告发起人 |
| “帮我**私聊**一下 小明，问明天几点到” | 按群名册里的昵称找到小明并私聊 |
| “帮我**私信**张三，说我会晚到十分钟” | 私聊张三 |
| “帮我跟 @张三 说一声，明天下午三点集合” | 在群里 @ 张三 说这句话 |
| “**在群里** @ 他一下，提醒带材料” | 在群里 @ 对方 |

规则（插件会再校验一次，不只看模型自觉）：

1. 只要指令里出现 **私聊 / 私信 / 私下 / 悄悄 / 单独 / 小窗 / 私密 / dm / pm** 等字样，就走私聊。
2. 没有这些字样、且当前在群里，就走群内 @ 目标发送。
3. 在私聊窗口里给机器人下指令也可以，但同样要带“私聊”等字样；不带的话插件会要求说清楚，**不会**擅自把内容公开到群里。
4. 在群里明确说“在群里 @ 他 / 公屏 / 当众”时优先群内发送；“别在群里说”这类否定句不会误判成群发。

## 主要能力

- **只发一条**：按人格私聊一条，立即回报已发出；对方首次文字回复后，**用同一人格把原话修饰成转述**发给发起人，任务结束，后续由正常聊天接管。
- **窗口内跟转**：首次回复后的一段时间内，对方再发来消息，若 LLM 判断仍与先前话题相关，就继续按人格口吻转述给发起人；无关消息不转述。跟转有次数上限，且**只转述、不再向联系人发送任何内容**。
- **人格转述回报**：回报正文是原话经人格口吻改写后的转述，不增加事实、不删关键信息；原话仍保存在数据库里。转述生成失败时自动回退为原话并标注。
- **群名册**：每天定时（默认凌晨 4 点）通过 OneBot 拉取机器人所在群、群成员昵称与 QQ，存到本地 `roster.sqlite3`；群里 @ 机器人并 @ 别人时也会即时收录被 @ 的人。
- **按昵称私聊**：群内可直接说“私聊小明”，按名册匹配 QQ；同群精确匹配，私聊里只有跨群唯一时才匹配，避免同名误发。
- **群临时会话**：机器人没加对方好友、普通私聊发送失败时，自动改走群临时会话（`send_private_msg` + `group_id`，需 NapCat 等协议端支持）；仍失败会明确回报“未发送”。
- **退订私聊**：对方在私聊里发 `/td 2小时`、`/td 3天`、`/td 永久` 后，机器人不再主动私聊他，但群里 @ 他照常；`/td 取消` 恢复。
- **人格化确认**：工具成功后，插件会用同一人格另生成一句确认（如“主人～已经私聊小明啦”），并在发送前替换掉主模型的普通回复，避免出现“已经私聊转达了”这种没有语气的话。
- **长文本分条**：人格化转述、首条私聊或群内 @ 超过单条上限时，按句号/换行自动拆成多条发送，不再截断。
- **群内 @ 代说**：没有私聊字样时在群里 @ 目标说话，由模型简短确认，不跟踪群回复。
- **使用保存的人格**：可指定人格 ID；未指定时读取发起会话实际生效的人格（含会话级覆盖）。只复制提示词与风格样例，不转发发起会话历史、密钥、工具或长期记忆。
- **自动回报**：私聊任务的详细结果固定发到发起人在原平台的私聊，不回到群里复述。
- **权限与黑名单**：默认所有人都能用，只有黑名单被拒绝；管理员（AstrBot 的 `admins_id` 加 `extra_admins`）可以在聊天里拉黑、解除拉黑、查看黑名单。目标必须来自真实 @、群名册昵称、明确 QQ 号或 contacts，不凭空猜；同一联系人同时只有一条私聊任务，全局最多 20 条。
- **以发起人为主语**：私聊首条会明确写成“云理（发起人昵称）希望我转告你……”；委托内容里的“我／找我／我的”都会改写成发起人，不会被当成机器人或人格自己；不再声明“我是机器人”。
- 只支持文字。不自动加好友、不查陌生人、不发媒体、不跨平台搜索。

## 安装

1. 建议 **AstrBot 4.29.1 或更新版本、Python 3.10+**。已在云端 AstrBot 4.29.1 上核对所需接口（人格解析、`llm_generate`、`send_message`、`At`、工具注册）；尚未在真实群聊里联调，旧版不保证兼容。
2. 把整个 `astrbot_plugin_persona_delegate` 文件夹复制到 AstrBot 的 `data/plugins/`，或通过插件管理器导入当地 ZIP。不要只复制 main.py。
3. 重启 AstrBot 或重载插件；默认所有人可用，按需在配置里填黑名单（以及可选的 contacts），保存并重载。
4. 在 AstrBot 设置中启用聊天模型工具调用，并允许工具 `persona_relay_message` 与 `persona_chat_control`；人格若限制了工具，也要把这两项加入。群聊通常需要 @机器人 触发。
5. 在 AstrBot 人格管理中建立人格；发起会话选中它，或在指令里明确人格 ID。

本插件只使用 Python 标准库和 AstrBot SDK，无额外 pip 依赖。

## 配置示例

适配器实例 ID 假设为 `qqbot`，你的账号是 `111111`：

```json
{
  "blocked_users": [],
  "extra_admins": [],
  "contacts": ["张三=qqbot:FriendMessage:222222"],
  "allow_mentions": true,
  "allow_raw_target": false,
  "provider_id": "",
  "persona_style_extra": "",
  "persona_status_reports": true,
  "max_message_chars": 1200,
  "timeout_seconds": 300,
  "followup_window_seconds": 1800,
  "followup_max_relays": 10,
  "allow_nickname_target": true,
  "roster_sync_enabled": true,
  "roster_sync_hour": 4,
  "roster_sync_timezone": "Asia/Shanghai",
  "temp_session_enabled": true,
  "llm_timeout": 60,
  "retention_days": 7
}
```

**注意：** `qqbot` 必须是你实际的适配器实例 ID（在适配器配置或日志的 unified_msg_origin 中核对），不是固定值，也不一定是 `aiocqhttp` / `telegram` 这类类型名。会话格式为 `平台实例ID:FriendMessage:账号`。

- `allow_mentions`（默认开）：口语里 @对方或直接写 QQ 号即可当目标。关闭后只能使用 contacts 联系人。
- `allow_raw_target`（默认关）：只影响其他任意账号写法；@、QQ 号、contacts 已经够用，通常无需开启。
- `contacts` 是可选的别名/白名单，适合常用联系人。
- `provider_id` 留空跟随发起会话；填写时用 AstrBot 里的提供商 ID。私聊消息和跟转转述都由该模型按人格生成。
- `persona_style_extra`：额外风格要求，追加到人格提示词后，例如“称呼我主人、句尾带～、多用颜文字”；留空只用保存的人格。
- `persona_status_reports`：状态回报人格化，默认开；“已传达/对方还没回”会用人格口吻发，关掉则发机械格式。
- `max_message_chars`：单条消息最大字数，默认 1200；私聊首条、转述回报、群内 @ 超过这个长度时，会按句号/换行自动拆成多条发送。
- `timeout_seconds`：发出私聊后等待回复的时长，默认 300 秒；超时任务结束并回报。
- `followup_window_seconds`：首次回复后的跟转窗口，默认 1800 秒；填 0 关闭跟转。
- `followup_max_relays`：单个任务最多跟转次数，默认 10；填 0 关闭跟转。
- `allow_nickname_target`：允许用群昵称指定对象，默认开。
- `roster_sync_enabled` / `roster_sync_hour` / `roster_sync_timezone`：每天在指定时区的小时（默认 Asia/Shanghai 的 4 点）同步群名册；也可用 `/代聊 名册` 手动立即同步。
- `temp_session_enabled`：普通私聊失败时改用群临时会话，默认开；需要协议端支持。

## 使用样例（QQ 群）

```text
@机器人 帮我私聊一下 @小明，问他明天几点到
@机器人 帮我私信一下 222222，说我今晚加班，晚点回
@机器人 帮我跟 @小明 说一声，明天下午三点集合
@机器人 在群里 @ 他一下，提醒带材料
```

私聊窗口里同样可以：

```text
帮我私聊一下 222222，问明天几点到
看看我的代聊进行到哪了
取消我发起的所有代聊任务
有哪些保存的人格？
```

模型应把目标理解为“消息里 @ 的人 / 直接给的 QQ 号 / 已配置别名”。**消息里真实的 @ 优先**：即模型把昵称写错，也以被 @ 的账号为准。如果模型没调用工具、或把“私聊”理解错，先检查工具调用记录；工具返回的才是真实状态。

确定性管理命令（同样受权限约束，群聊和私聊都可用）：

```text
/代聊 进度
/代聊 取消
/代聊 取消 任务ID
/代聊 联系人
/代聊 名册
/代聊 人格
/代聊 拉黑 123456
/代聊 解除拉黑 123456
/代聊 黑名单
```

## 退订私聊（/td）

任何人在私聊里发：

```text
/td 2小时
/td 3天
/td 永久
```

机器人就会停止主动私聊他；退订期间群里 @ 他、群内代说照常。恢复用：

```text
/td 取消
```

- 进行中的私聊任务会立即停止，并向发起人发送**按人格口吻**写的通知：“对方在 2 小时/3 天/永久内不想收到机器人私聊”。
- 之后有人试图私聊他，会直接提示“对方已退订私聊（还剩 X）”，只能群内 @。
- 退订只拦截机器人主动私聊（任务消息、回报、群临时会话），不阻止对方回复或群内互动。
- 到期自动失效；时长范围 1 小时到 10 年，永久用“永久”。
- 退订记录存在 `optout.sqlite3`，只影响对应平台账号。

## 权限与黑名单

- **默认所有人可用**：只要能触发机器人（群里 @ 或私聊），就可以发起代聊，没有白名单限制。
- **静态黑名单**：配置 `blocked_users` 填 `平台:账号` 或纯账号，重启/重载后一直生效。
- **运行期黑名单**：管理员直接说“拉黑 123456”“解除拉黑 123456”“看看黑名单”，或用上面的 `/代聊` 命令；记录保存在 `blocklist.sqlite3`。
- **管理员**：AstrBot 配置里的 `admins_id`，加上插件配置 `extra_admins`。管理员不受黑名单影响，也不能被拉黑或拉黑自己。
- 被拉黑的人发起时只会收到“你已被管理员禁止使用代聊”，不会执行任何发送。
- 默认放行意味着任何群成员都能让机器人私聊别人；如果群很大或担心滥用，建议把常用群加入观察、按需拉黑，或把 `roster`/`temp_session` 相关能力关掉。全局同时最多 20 条活动任务。

## 对方回复之后

- 插件把**这一次**回复按保存的人格口吻转述给你（不是逐字转发），完成回报本身就是人格化转述，不再套“【代聊回报】”的机械模板头；这条私聊继续走 AstrBot 正常对话，对方可以自然地接着聊。
- 首次回复后的 **30 分钟（可配置）** 内，对方再发来的消息会先由 LLM 判断是否仍与先前话题相关：相关才继续发一条人格化跟转，不相关就不打扰你。
- 每次成功跟转会顺延窗口，但总数受 `followup_max_relays`（默认 10）限制；窗口或次数用尽后不再跟转，正常聊天不受影响。
- **跟转只写给你看，不会再发给联系人**；正文是转述，不是联系人原话的逐字复制。
- 转述只改语气措辞、不改事实；原话完整保存在任务数据库，转述失败会自动改发原话并标注“人格转述失败”。
- 正常对话使用**对方私聊会话实际生效的人格和模型**，可能与发起人会话选中的人格不同。想让风格一致，可把同一人格绑定到该私聊会话（AstrBot 的会话人格设置）。
- 代发消息不写入对方会话的聊天历史，正常对话接管时模型可能看不到上一句；对方的回复通常已包含所需信息，必要时可让对方复述或由机器人自然追问。
- 发起人收到的回报会明确“仅代表消息已送达对方，不证明线下事项完成”。

## 群名册与临时会话

- **每日同步**：默认每天 4 点（Asia/Shanghai，可配置时区）执行一次，调用 OneBot 的 `get_group_list` 与 `get_group_member_list`，记录机器人所在群、群名称和成员昵称/群名片/QQ。也可随时用 `/代聊 名册` 手动同步。
- **@ 即时收录**：群里有人 @ 机器人、同时 @ 了其他人时，被 @ 的人会立刻写入名册；即使当天还没同步，也能按昵称找到。
- **昵称匹配**：群里说“私聊小明”会先在该群名册里精确匹配昵称/群名片/QQ；在私聊窗口里只有跨群唯一时才匹配。同名不唯一时不会猜，要求改用 @ 或 QQ 号。
- **非好友私聊**：普通私聊发送失败（如未加好友）时，若知道共同群，会自动调用 `send_private_msg` 并带 `group_id` 走群临时会话。该能力依赖协议端实现（NapCat 的接口支持 `group_id`），失败会如实回报“未发送”，不会假装成功。
- **隐私**：名册包含群成员的昵称与 QQ，只保存在机器人本机 `data/plugin_data/astrbot_plugin_persona_delegate/roster.sqlite3`；停用插件不会自动删除。请限制服务器访问权限，并按需清理。

## 平台限制

插件使用 AstrBot 标准 `Context.send_message` 与 `At` 组件，不依赖特定 QQ 实现。**并非所有平台都支持任意主动私聊或 @：**

- QQ OneBot 类适配器通常要求对方已是好友；临时会话是否可用由协议端决定。
- Telegram 通常要求对方先与机器人建立会话；@ 需要对方在本群。
- QQ 官方 API 目前不支持该通用主动发送入口。
- 微信等适配器的主动发送、@ 渲染和账号格式由具体实现决定，本插件未逐一验证。

发送接口不报错只表示提交成功，不保证送达、已读，更不代表线下事项完成。对方发非文字消息时，任务会继续等待文字回复或超时，不臆测图片/语音内容。群内 @ 发送不跟踪回复，也不列入 `/代聊 进度`、不做去重持久化：如果发送成功后进程立即崩溃，可能已经发出但没有记录，请勿立即重发。

## 任务状态与可靠性

- `waiting`：私聊已发出，等待回复；默认发一条人格化的“我已经传达过去了，等他回复就告诉你”，不是目标完成。
- `completed`：已收到对方回复并按人格转述；原话可在任务记录中核对。
- `failed`：生成或发送失败。网络超时可能平台已接收，**插件不会自动重发**。
- `timeout`：等待回复超时；默认发一条人格化的“对方还没回”通知。
- `cancelled`：发起者取消。
- `interrupted`：重启时发现未完成任务；停止恢复发送并回报，避免重复打扰。

回报先落盘再发送，约每 10 秒重试一次，失败按 5/10/20… 秒退避、上限 1 小时；极端情况下可能重复投递（at-least-once），不能宣称“恰好一次”。机器人离线时不计时也不推送，上线后处理过期任务。所有操作串行执行，单次网络等待有超时，但高延迟时其他任务会延后。

跟转窗口内，对方每发一条消息会先做一次相关性判断（1 次模型调用），判断为相关时再做一次人格转述（再 1 次），因此最多 2 次调用；无关消息只花 1 次。跟转不改变任务状态（仍是 `completed`），只再发一条人格化转述。

数据库位于 AstrBot 插件数据目录（通常 `data/plugin_data/astrbot_plugin_persona_delegate/tasks.sqlite3`），内含人格提示词快照、目标与本次对话，默认保留 7 天；待发送回报可能保留更久。停用插件不会自动删除数据库。

对方消息不会获得控制工具或发起者历史，但 LLM 生成并非安全证明，不能完全抵御提示注入。不要用于付款、共享密码、签合同等需要人工确认的高风险事项。群内 @ 的内容是公开的，发送前请确认措辞。

上线前建议：

1. 登记一个愿意配合的测试账号，先确认你能收到机器人的主动私聊。
2. 单次私聊“测试消息”，确认发送回报和回复转告。

5. 任务进行中重启 AstrBot，确认中断报告且不重发给对方。
